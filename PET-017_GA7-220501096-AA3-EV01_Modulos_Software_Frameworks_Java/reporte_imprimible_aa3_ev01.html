1. Introducción y Objetivos

En la ingeniería de software actual, el uso de frameworks ágiles permite a los equipos de desarrollo reducir drásticamente la complejidad accidental, acelerar los ciclos de entrega continua y garantizar una arquitectura estandarizada y modular. En el ecosistema Java empresarial, Spring Boot representa la tecnología dominante para la construcción de APIs REST robustas y microservicios de alto rendimiento.

La presente evidencia da cumplimiento a GA7-220501096-AA3-EV01, evolucionando el sistema de información de la Pizzería Bella Italia hacia una arquitectura orientada a servicios desacoplada construida con Spring Boot 3.2.5. Se implementaron entidades mapeadas con JPA (Java Persistence API) y gestionadas por Hibernate, repositorios basados en Spring Data JPA, capa de negocio con validaciones automáticas y controladores REST que exponen servicios JSON consumibles desde aplicaciones web y móviles.

🎯 Objetivos Específicos Alcanzados:
  • Estructurar un proyecto backend modular con Spring Boot 3 y Maven, definiendo dependencias de persistencia, validación y testing.
  • Modelar entidades JPA con llaves primarias, foráneas, restricciones de longitud y propagación en cascada.
  • Crear repositorios desacoplados con JpaRepository y consultas derivadas por métodos.
  • Implementar la lógica transaccional de pedidos calculando subtotales y garantizando consistencia ACID.
  • Exponer una API REST completa con controladores anotados (@RestController) y captura global de excepciones.
  • Verificar la solución mediante pruebas unitarias JUnit 5 y empaquetar el JAR ejecutable en Docker.

4. Persistencia Relacional con Spring Data JPA y Hibernate

A continuación se detalla la configuración y mapeo entidad-relación de las entidades del dominio de la Pizzería Bella Italia:

Anotaciones de Persistencia y Validación Implementadas:
  • @Entity y @Table: Vinculación con las tablas CLIENTES, PIZZAS, PEDIDOS y DETALLE_PEDIDO.
  • @Id y @GeneratedValue(strategy = GenerationType.IDENTITY): Gestión automática de claves autonuméricas.
  • @ManyToOne y @OneToMany: Relaciones de integridad referencial con propagación de operaciones (cascade = CascadeType.ALL) y eliminación de huérfanos.
  • @NotBlank, @Pattern, @DecimalMin: Validaciones automáticas en tiempo de ejecución.

Servicio Transaccional de Pedidos (`PedidoService.java` - Fragmento):

@Service
@Transactional(readOnly = true)
public class PedidoService {
    @Autowired private PedidoRepository pedidoRepository;
    @Autowired private ClienteRepository clienteRepository;
    @Autowired private PizzaRepository pizzaRepository;

    @Transactional
    public Pedido crearPedido(PedidoRequestDTO request) {
        Cliente cliente = clienteRepository.findById(request.getIdCliente())
            .orElseThrow(() -> new IllegalArgumentException("Cliente no existe"));

        Pedido pedido = new Pedido();
        pedido.setCliente(cliente);
        pedido.setFechaPedido(LocalDateTime.now());
        pedido.setEstado(request.getEstado());

        BigDecimal total = BigDecimal.ZERO;
        for (ItemPedidoDTO item : request.getItems()) {
            Pizza pizza = pizzaRepository.findById(item.getIdPizza())
                .orElseThrow(() -> new IllegalArgumentException("Pizza no existe"));
            BigDecimal subtotal = pizza.getPrecio().multiply(BigDecimal.valueOf(item.getCantidad()));
            total = total.add(subtotal);

            DetallePedido det = new DetallePedido(pizza, item.getCantidad(), pizza.getPrecio());
            pedido.agregarDetalle(det);
        }
        pedido.setTotal(total);
        return pedidoRepository.save(pedido);
    }
}
