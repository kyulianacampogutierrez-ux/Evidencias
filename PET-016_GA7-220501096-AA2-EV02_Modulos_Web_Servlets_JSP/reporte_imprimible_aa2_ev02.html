1. Introducción y Objetivos

En el desarrollo de aplicaciones empresariales escalables con tecnologías Java EE / Jakarta EE, la implementación del patrón arquitectónico Modelo-Vista-Controlador (MVC) constituye un estándar fundamental para lograr la separación rigurosa de responsabilidades entre la lógica de negocio, los controladores de flujo de navegación y la presentación visual interactiva.

La presente evidencia da cumplimiento estricto a GA7-220501096-AA2-EV02, evolucionando el módulo de persistencia JDBC desarrollado previamente en la evidencia AA2-EV01 hacia una aplicación web dinámica completa para el sistema de gestión de la Pizzería Bella Italia. Se implementaron controladores basados en Servlets Java (HttpServlet), vistas dinámicas estructuradas con JavaServer Pages (JSP) y formularios web que procesan transacciones CRUD mediante los métodos estándar GET y POST.

🎯 Objetivos Clave de la Evidencia:
  • Codificar los controladores web utilizando Servlets Java mapeados con anotaciones estándar @WebServlet.
  • Gestionar el ciclo de vida de peticiones HTTP discriminando adecuadamente doGet (despacho, consultas y listados) y doPost (procesamiento de altas, modificaciones y transacciones de pedidos).
  • Construir vistas dinámicas JSP con directivas de página, bibliotecas JSTL y diseño responsivo adaptado al SENA.
  • Conectar la capa controladora con los patrones DAO y la base de datos relacional MariaDB contenida en Docker.
  • Empaquetar el artefacto en formato WAR (Web Application Archive) y verificar su ejecución contenedorizada.

3. Implementación de Servlets y Ciclo de Petición HTTP

3.1. ClienteServlet.java (/clientes)

Extiende de HttpServlet y está anotado con @WebServlet(name = "ClienteServlet", urlPatterns = {"/clientes"}). Administra el flujo completo de clientes:

  • Método doGet(HttpServletRequest, HttpServletResponse): Detecta acciones de borrado (action=eliminar) o edición (action=editar) mediante parámetros de consulta. Por defecto, recupera la lista completa invocando clienteDAO.listarTodos(), la inyecta en el objeto de petición mediante request.setAttribute("clientes", lista) y transfiere el control a la vista con request.getRequestDispatcher("/clientes.jsp").forward(request, response).
  • Método doPost(HttpServletRequest, HttpServletResponse): Extrae de forma segura los parámetros idCliente, nombre, telefono y direccion. Aplica la estrategia Post/Redirect/Get (PRG) redireccionando al cliente mediante response.sendRedirect(...) para prevenir reenvíos involuntarios al refrescar.
@WebServlet(name = "ClienteServlet", urlPatterns = {"/clientes"})
public class ClienteServlet extends HttpServlet {
    private ClienteDAO clienteDAO;

    @Override
    public void init() {
        this.clienteDAO = new ClienteDAO();
    }

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        String action = req.getParameter("action");
        if ("eliminar".equalsIgnoreCase(action)) {
            int id = Integer.parseInt(req.getParameter("id"));
            clienteDAO.eliminar(id);
            resp.sendRedirect(req.getContextPath() + "/clientes?msg=deleted");
            return;
        }
        req.setAttribute("clientes", clienteDAO.listarTodos());
        req.getRequestDispatcher("/clientes.jsp").forward(req, resp);
    }

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        req.setCharacterEncoding("UTF-8");
        int id = Integer.parseInt(req.getParameter("idCliente"));
        String nombre = req.getParameter("nombre");
        String tel = req.getParameter("telefono");
        String dir = req.getParameter("direccion");
        Cliente c = new Cliente(id, nombre, tel, dir);
        if (id > 0) clienteDAO.actualizar(c);
        else clienteDAO.insertar(c);
        resp.sendRedirect(req.getContextPath() + "/clientes?msg=saved");
    }
}

3.2. PizzaServlet.java (/pizzas)

Gobierna el catálogo gastronómico de especialidades. En su método doGet obtiene los productos activos, mientras que su método doPost parsea tipos de datos numéricos (precios en pesos colombianos) y persiste las nuevas pizzas con su tamaño tipificado.

3.3. PedidoServlet.java (/pedidos)

Coordina la interacción transaccional del módulo de ventas. Su método doGet precarga en simultáneo las listas de clientes y pizzas para alimentar las etiquetas <select> del formulario interactivo. El método doPost recibe el cliente seleccionado, el código de pizza y la cantidad, calcula el subtotal y delega en pedidoDAO.registrarPedido(pedido), el cual efectúa un commit transaccional atómico protegiendo la integridad referencial.

4. Vistas Dinámicas con JavaServer Pages (JSP) y Formularios HTML5

Estructura de Vistas Desarrolladas:

Todas las vistas incorporan la barra de navegación institucional, etiquetas semánticas HTML5 (header, nav, main, footer) y diseño responsivo adaptado a dispositivos móviles y escritorios.

Vista JSP Componentes HTML & Formularios Función Operativa y Dinamismo JSP
index.jsp Tarjetas de resumen métrico (KPIs), botones de acción rápida. Consulta contadores en tiempo real (clientes, catálogo, órdenes) y presenta la bienvenida corporativa de la pizzería.
clientes.jsp <form action="clientes" method="post"> con campos de texto, teléfono y dirección. Tabla dinámica que itera clientes con scriptlets/JSTL, botones para editar (GET con parámetro) y eliminar.
pizzas.jsp <form action="pizzas" method="post"> con selector de tamaños y campos numéricos. Visualización del menú en cuadrícula (grid) con precios formateados en moneda colombiana ($ COP).
pedidos.jsp <form action="pedidos" method="post"> con listas <select> vinculadas a entidades. Generación de comandas de venta, desglose del subtotal de pizzas e historial de pedidos registrados con sus detalles.
