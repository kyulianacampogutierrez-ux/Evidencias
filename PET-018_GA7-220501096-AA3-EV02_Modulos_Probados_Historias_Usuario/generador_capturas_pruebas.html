👤 HU-01: Registro y Validación Declarativa de Clientes (Bean Validation)
✓ CASO DE PRUEBA APROBADO

Requisito: El sistema debe validar que los nombres no estén vacíos (mínimo 3 caracteres), los teléfonos contengan únicamente entre 7 y 15 dígitos numéricos (Regex) y las direcciones sean detalladas. De lo contrario, debe rechazar la solicitud con HTTP 400 Bad Request.

Petición HTTP Inválida (Intento con Errores)
POST /api/clientes
{
  "nombre": "", // Error: Nombre vacío
  "telefono": "310-XYZ-00", // Error: Caracteres inválidos
  "direccion": "Cra 1" // Error: Longitud insuficiente
}
Respuesta Centralizada (GlobalExceptionHandler)
HTTP/1.1 400 Bad Request
{
  "timestamp": "2026-11-08 18:27:00",
  "status": 400,
  "error": "Error de Validación de Datos",
  "detalles": {
    "nombre": "El nombre no puede estar vacío",
    "telefono": "Debe contener entre 7 y 15 dígitos",
    "direccion": "Debe tener entre 5 y 200 caracteres"
  }
}
🍕 HU-02: Catálogo de Especialidades y Validación de Precios Mínimos
✓ CASO DE PRUEBA APROBADO

Requisito: Las pizzas deben contener un tamaño estandarizado (*Personal, Mediana, Grande, Familiar*) y una tarifa mínima de $5.000 COP protegida por @DecimalMin.

Filtro por Rango de Precios
GET /api/pizzas/precio-maximo?precio=35000.00
[
  {
    "idPizza": 1,
    "nombre": "Pizza Margarita",
    "tamano": "Mediana",
    "precio": 28000.00
  },
  {
    "idPizza": 5,
    "nombre": "Pizza Napolitana",
    "tamano": "Mediana",
    "precio": 32000.00
  }
]
Intento de Registro con Precio Inválido
HTTP/1.1 400 Bad Request
POST /api/pizzas
{ "nombre": "Mini Pizza", "precio": 2500.00 }

// Respuesta:
{
  "status": 400,
  "detalles": {
    "precio": "El precio mínimo permitido es de $5.000 COP"
  }
}
📦 HU-03: Creación Transaccional de Comandas y Cálculo Automático de Subtotales
✓ CASO DE PRUEBA APROBADO

Requisito: El módulo debe recibir la lista de ítems, consultar el precio vigente de cada especialidad en la base de datos, calcular los subtotales unitarios y consolidar el gran total de forma atómica en una única transacción ACID.

Petición POST con Desglose de Ítems
POST /api/pedidos
{
  "idCliente": 4,
  "estado": "En Preparación",
  "items": [
    { "idPizza": 2, "cantidad": 1 }, // 1 x $42.000
    { "idPizza": 6, "cantidad": 2 }  // 2 x $34.000 = $68.000
  ]
}
Comanda Generada con Totales Exactos
HTTP/1.1 201 Created
{
  "idPedido": 4,
  "cliente": { "nombre": "David Martinez" },
  "total": 110000.00, // 42.000 + 68.000 = 110.000 COP
  "estado": "En Preparación",
  "detalles": [
    { "pizza": "Pepperoni", "subtotal": 42000.00 },
    { "pizza": "Vegetariana", "subtotal": 68000.00 }
  ]
}
🔄 HU-04: Flujo Operativo y Transición de Estados de Despacho (PATCH)
✓ CASO DE PRUEBA APROBADO

Requisito: Permitir actualizar el estado del pedido a lo largo del ciclo de vida gastronómico (*En Preparación -> En Horno -> En Reparto -> Entregado*).

Actualización Parcial con Método PATCH
PATCH /api/pedidos/4/estado?nuevoEstado=En Horno
// Cabecera:
PATCH /api/pedidos/4/estado?nuevoEstado=En+Horno HTTP/1.1
Host: localhost:8082
Content-Length: 0
Respuesta con Estado Actualizado
HTTP/1.1 200 OK
{
  "idPedido": 4,
  "total": 110000.00,
  "estado": "En Horno", // Estado confirmado
  "fechaPedido": "2026-11-08 18:28:25"
}
