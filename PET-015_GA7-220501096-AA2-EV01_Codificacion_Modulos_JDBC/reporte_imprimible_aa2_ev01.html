1. Introducción y Justificación Técnica

En la fase de ejecución del programa formativo ADSO (Actividad de Proyecto 7: Codificar los módulos del software), el componente de acceso a datos constituye el cimiento de confiabilidad de cualquier solución de software. La tecnología Java Database Connectivity (JDBC) ofrece una interfaz de bajo nivel de alto rendimiento que conecta el lenguaje Java con sistemas relacionales basados en SQL.

La presente evidencia, codificada bajo la referencia GA7-220501096-AA2-EV01, traslada el diseño físico de bases de datos formulado en fases anteriores (archivo GA6-220501096-AA2-EV03.tsql) a una implementación funcional orientada a objetos para el sistema de la Pizzería Bella Italia. Se aplica el patrón de diseño DAO (Data Access Object) y la separación de capas (Modelo, Utilidades, DAO y Aplicación), mitigando el acoplamiento y previniendo vulnerabilidades como la inyección de código SQL.

Resumen de Características Técnicas Desarrolladas:
• Lenguaje: Java 17 LTS (Eclipse Temurin JDK) gestionado con Apache Maven 3.9.
• RDBMS: MariaDB 10.5 / MySQL 8.0 con motor transaccional InnoDB.
• Entidades: Clientes, Pizzas (Catálogo), Pedidos (Cabecera) y DetallePedido (Líneas de venta).
• Operaciones: CRUD completas (Create, Read, Update, Delete) + Transacciones atómicas ACID.
• Orquestación: Docker Compose modular (servicios db, backend-java y test-runner).

4. Implementación del Acceso a Datos (JDBC & CRUD)

4.1. Conexión Parametrizada y Resiliente (`ConexionBD.java`)

public static Connection getConexion() throws SQLException {
    String host = System.getenv("DB_HOST") != null ? System.getenv("DB_HOST") : "localhost";
    String port = System.getenv("DB_PORT") != null ? System.getenv("DB_PORT") : "3306";
    String database = System.getenv("DB_NAME") != null ? System.getenv("DB_NAME") : "pizzeria";
    String user = System.getenv("DB_USER") != null ? System.getenv("DB_USER") : "karen";
    String password = System.getenv("DB_PASS") != null ? System.getenv("DB_PASS") : "choco";

    String url = String.format("jdbc:mariadb://%s:%s/%s?useSSL=false&allowPublicKeyRetrieval=true",
            host, port, database);
    return DriverManager.getConnection(url, user, password);
}

4.2. Inserción Segura y Generación de Llaves (`ClienteDAO.java`)

public boolean insertar(Cliente cliente) {
    String sql = "INSERT INTO CLIENTES (Nombre, Telefono, Direccion) VALUES (?, ?, ?)";
    try (Connection conn = ConexionBD.getConexion();
         PreparedStatement stmt = conn.prepareStatement(sql, Statement.RETURN_GENERATED_KEYS)) {
        stmt.setString(1, cliente.getNombre());
        stmt.setString(2, cliente.getTelefono());
        stmt.setString(3, cliente.getDireccion());
        if (stmt.executeUpdate() > 0) {
            try (ResultSet rs = stmt.getGeneratedKeys()) {
                if (rs.next()) cliente.setIdCliente(rs.getInt(1));
            }
            return true;
        }
    } catch (SQLException e) { System.err.println(e.getMessage()); }
    return false;
}

4.3. Transaccionalidad Atómica ACID (`PedidoDAO.java`)

Para asegurar que un pedido se registre únicamente si todos sus ítems de detalle son almacenados con éxito, se desactiva el auto-commit y se gestionan las confirmaciones mediante commit() o retroceso con rollback() ante cualquier anomalía: 

conn.setAutoCommit(false); // Inicia transacción atómica
// 1. Inserción en tabla PEDIDOS
stmtPedido.executeUpdate();
int idPedido = obtenerIdGenerado(stmtPedido);

// 2. Inserción en batch sobre DETALLE_PEDIDO
for (DetallePedido item : pedido.getDetalles()) {
    stmtDetalle.setInt(1, item.getCantidad());
    stmtDetalle.setDouble(2, item.getSubtotal());
    stmtDetalle.setInt(3, idPedido);
    stmtDetalle.setInt(4, item.getIdPizza());
    stmtDetalle.addBatch();
}
stmtDetalle.executeBatch();
conn.commit(); // Confirmación atómica si todo fue exitoso
